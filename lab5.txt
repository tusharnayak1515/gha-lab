1. Create a deliberately misconfigured workflow that does not trigger for a push. Diagnose and fix it by checking the workflow file path, YAML syntax, event and branch filters, path filters, default branch, and repository Actions settings. Record the cause.
2. Make a prerequisite job fail and observe how a dependent job with needs is skipped. Add a reporting job that runs after the dependency regardless of success or failure, but not after cancellation. Confirm it reports the dependency result.
3. Make CI use an incorrect Node.js version or working directory, then diagnose the failure from the Actions logs. Pin the intended tool version and print useful, non-sensitive environment diagnostics.
4. Add caching keyed by operating system and lockfile hash. Change the lockfile and confirm a new cache key is used. Check that the cache is only an optimization and the workflow still installs correct dependencies on a cache miss.
5. Add a network-dependent test step with an explicit timeout, bounded retries, and backoff. Ensure retrying is safe and does not duplicate a non-idempotent deployment or data mutation.
6. Add a GitHub Actions job summary containing test totals, artifact version, and deployment health-check result. Confirm the summary is useful while excluding secrets, tokens, and unnecessary sensitive data.
7. Compare workflow duration and runner minutes before and after using caching, path filters, parallel jobs, and a smaller matrix. Keep required security checks and deployment gates enabled, and document the tradeoffs.
8. Simulate a broken production deployment workflow in a test repository. Triage the failing run, restore a known-good workflow or deployment path, validate the deployed version, and write down a prevention action such as a workflow test, review rule, or rollback check.
